# Phase 7 completion programme: Phase 1 reconciliation

This is the execution plan for the six agreed completion phases. It consolidates the existing source-derived Phase 1 audits and assigns every curated language element to a primary semantic migration phase and later hardening obligations. It does not certify any element as conformant. The machine-readable allocation is `PHASE7-COMPLETION-PLAN.json`, generated by `build_completion_plan.py`.

## Baseline and authority

The supplied local source tree is the authority for this plan. `LANGUAGE-ELEMENTS.json` currently lists 267 elements, including 19 functions. The portable corpus has 11 normative cases, but the registry has no approved element associations. These facts must not be conflated: an approved query result does not automatically certify every feature it happens to exercise. `PHASE1-COMPLETENESS.json`, `PHASE1-COVERAGE-ASSESSMENT.json`, `FUNCTION-SEMANTIC-AUDIT.json` and `COVERAGE-GAP-MATRIX.json` remain the detailed discovery evidence.

## Phase 1 decisions

- Use the seven existing coverage dimensions: valid syntax, invalid syntax, semantics, types and NULL, boundaries, interactions and adversarial cases. Each applicable dimension eventually needs independently reviewed evidence or a justified not-applicable decision.
- Migrate ordinary language semantics as portable YT-SQL queries with independently authored JSON expectations. Do not derive normative expectations from Python or Rust execution. Keep the existing Python assertions until their residual value is reviewed.
- Assign core language and relational elements to Phase 2, and functions, collections, text, Unicode and temporal elements to Phase 3. Every element also receives Phase 4 adversarial review, Phase 5 differential review and Phase 6 certification. These are work allocations, not assertions that every dimension applies to every element.
- Treat `CROSS`, `FULL`, `NATURAL`, `RECURSIVE` and `RIGHT` as recognised unsupported forms needing reviewed negative tests. Do not register them as supported solely because the parser recognises their spelling.
- Stable ordering, tie-breaking and pagination require extensive deterministic fixtures and exact ordered expectations wherever the language defines an order. Unspecified ties must not acquire invented guarantees through tests.
- Unicode guarantees must be checked on each supported platform and relevant runtime/library combination, with version dependencies explicitly documented. Python/Rust agreement alone is insufficient evidence of a platform-independent contract.
- Preserve the existing source-derived inventories and drift checks. The completion plan's generator refuses unexpected changes to the coverage-dimension contract.

## Exit and follow-on work

Phase 1 closes **planning and traceability only**: all currently curated elements have explicit phase ownership, unsupported grammar has a negative-test queue, and the normative expectation and evidence rules are fixed. Phase 1 does not close the 267 pending semantic reviews. Phase 2 and Phase 3 must resolve these reviews through independently established expectations. Phase 4 adds adversarial and negative evidence; Phase 5 establishes execution and platform parity; Phase 6 enforces reviewed evidence for every applicable dimension and documents any justified exceptions.

Run `python yt-sql/build_completion_plan.py --check` when explicitly checking whether the generated planning artefact needs regeneration. This is a maintenance check, not a semantic test or evidence of YT-SQL correctness. Behavioural conformance must be established by executing YT-SQL against independently authored expectations. The complete local quality gate remains required for acceptance on the development machine.
